About Training Tracker Classic

The app that started it all, and why it almost didn't.

Training Tracker Classic - v1.0 - was built out of genuine need and a lot of ambition for someone who barely knew HTML and CSS at the time. The idea was simple: help managers at a Chick-fil-A store track how new hires were progressing through positions like iPads, Register, Drive Through, Staging, and more.

The honest truth? It was pretty scuffed. Instead of a real database, all the data lived in a JSON file sitting on the server. SQL and databases felt way too intimidating to even try. That meant every single person on the team was reading from and writing to the same flat file at the same time, with zero concurrency handling. Race conditions were basically a feature.

It was hosted on a free service called Glitch, which would spin the server completely down after a few minutes of inactivity. Every time someone opened it up during a shift, they had to wait for a cold start. No profiles, no real accounts, no authentication. Anyone with the link could open it and change anything.

On mobile? Forget it. The layout was built for a desktop and a desktop only. Floats, hardcoded widths, pixel-specific margins that broke the moment you opened it on a phone. It was clearly put together by someone watching YouTube tutorials at midnight and hoping for the best.

Known issues at launch
No mobile support JSON file as the "database" No user profiles Everyone editing the same file Glitch hosting (cold starts) No authentication No real-time updates Painfully slow on any network Poor design No data backups

It took months to build. This was pre-AI, pre-Copilot, pre-anything that would help you get unstuck in five minutes. Every bug meant digging through Stack Overflow threads and rewatching tutorial videos to find what went wrong. Every feature felt like a small victory.

The app was abandoned shortly after it was tried in the store. The real world exposed every crack immediately. It couldn't handle multiple people using it at once, it was too slow to be practical during a rush, and nobody wanted to open a laptop just to log a training session.

But that failure wasn't wasted. Every frustration, every workaround, every "why doesn't this work" moment became a lesson. The app that exists now - with a real database, proper authentication, mobile-first design, roadmaps, smart scheduling, session ratings, and everything else - exists because this one failed in exactly the right ways at exactly the right time.

Sometimes the best thing a project can do is fall apart and show you what to build next. 🐔
